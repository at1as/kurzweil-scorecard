# Canonical prediction field guide

`src/lib/model.ts` is the authoritative Zod schema and inferred TypeScript `Prediction` type. `src/lib/validation.ts` enforces cross-record and chronological integrity. The site uses supplied v0.2 editorial verdicts when a release payload is present; legacy fixture verdicts remain derived. Statistics are recomputed from eligibility flags, with no fractional weights.

| Field                                                | Meaning and rule                                                                                                                                                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                                                 | Stable uppercase alphanumeric/hyphen record identifier; also the permanent URL segment. Never reuse an excluded ID.                                                                                               |
| `familyId`                                           | Related forecast lineage, including materially revised deadlines. Nullable until researched.                                                                                                                      |
| `parentStatementId`                                  | Original sentence/paragraph from which an atomic claim came. Preserve quantity/adoption constraints when splitting.                                                                                               |
| `duplicateOf`                                        | Existing retained original record, or null. No duplicate chains. Duplicates cannot be canonical.                                                                                                                  |
| `canonical`, `scoringKey`                            | Explicit counting decision and unique claim/deadline identity. Two canonical objects cannot share a scoring key.                                                                                                  |
| `category`                                           | Exactly one of the thirteen primary workbook taxonomy names.                                                                                                                                                      |
| `tags`                                               | Secondary subcategory/mechanism tags, with no repetitions. They never create extra statistical votes.                                                                                                             |
| `claimType`                                          | `UNKNOWN`, `CAPABILITY`, `ADOPTION`, `PERFORMANCE_COST`, or `SOCIAL_INSTITUTIONAL`. Never infer an imported lead's type without review.                                                                           |
| `importedClaim`                                      | Preserved lead/paraphrase; immutable for imported records.                                                                                                                                                        |
| `originalWording`, `wordingKind`                     | Separately checked original text and `VERIFIED_QUOTE` or `VERIFIED_PARAPHRASE`; otherwise null plus `UNVERIFIED_PARAPHRASE`.                                                                                      |
| `normalizedClaim`                                    | Editorial, testable formulation; never substituted for original source text.                                                                                                                                      |
| `successCriteria`                                    | Full capability, quantity, adoption, price, technology, and other conditions that define fulfillment.                                                                                                             |
| `scope`                                              | Nullable population, geography, adoption stage, conditions, and units.                                                                                                                                            |
| `sources[]`                                          | Attribution references with ID, title, publication year, year-verification flag, URL, locator, and wording-verification flag. Multiple references are supported.                                                  |
| `deadline.originalText`                              | Original/legacy target wording retained verbatim.                                                                                                                                                                 |
| `deadline.precision`                                 | `UNCONFIRMED`, `YEAR`, `INTERVAL`, or `EXACT_DATE`. Unconfirmed targets have no confirmed numerical date fields.                                                                                                  |
| `deadline.year`, `startYear`, `exactDate`            | Confirmed endpoint, optional interval start, and exact calendar date. Interval endpoints must be justified in criteria/rationale; never assign a midpoint to a vague lead.                                        |
| `evidence[]`                                         | Independent outcome references with ID, title, real URL, nullable publication date, access date, stance (`SUPPORTS`, `CHALLENGES`, `CONTEXT`), and explanation. Source attribution alone is not outcome evidence. |
| `assessment.state`                                   | `UNREVIEWED`, `ATTRIBUTION_CHECKED`, `EVIDENCE_CHECKED`, `VERIFIED`, `EXCLUDED`.                                                                                                                                  |
| `assessment.scorable`                                | Null before review, true for fixed assessable claims, false for documented unscorable claims.                                                                                                                     |
| `assessment.atDeadline`                              | `FULL`, `PARTIAL`, `NOT_FULFILLED`, `NOT_DUE`, `UNASSESSABLE`, or `UNREVIEWED`. Historical outcome, not overwritten when realization occurs later.                                                                |
| `assessment.atReview`                                | `FULL`, `PARTIAL`, `NOT_FULFILLED`, `UNASSESSABLE`, or `UNREVIEWED`. Current snapshot assessment.                                                                                                                 |
| `firstAchievementYear`, `firstAchievementDate`       | First supported full realization, nullable. Never populate for partial/unmet claims. Exact dates and years must agree.                                                                                            |
| `lastReviewedAt`, `reviewer`, `confidence`           | ISO review date, reviewer attribution, `LOW`/`MEDIUM`/`HIGH`; required for verified records. The snapshot is not automatically a last-review date.                                                                |
| `rationale`, `disputed`, `alternativeInterpretation` | The primary reading and explanation; a disputed record must document the alternative. No silent change of criteria.                                                                                               |
| `exclusionReason`                                    | Required for excluded or duplicate records.                                                                                                                                                                       |
| `research`                                           | Notes, unresolved questions, and dated correction/review history.                                                                                                                                                 |
| `provenance`                                         | Input filename, SHA-256, CSV row (header is row 1), legacy ID, and a full string-to-string map of original fields.                                                                                                |

All sources, criteria, and evidence must be populated by actual research. An apparently complete schema does not prove historical truth; validation enforces consistency, while human research establishes correctness.

## Evidence release v0.2

`src/lib/evidence-model.ts` validates the immutable package. Each adapted record retains the entire authoritative object in `release`, including separate deadline/review outcomes, review state, source verification, publication provenance, target precision/interpretation, eligibility, documented-by bounds, exact/interval drift, and legacy relations. Read these original fields for semantic display rather than inferring from normalized browsing fields.

`ASSESSED` is an AI-assisted editorial assessment, not human verification. `SOURCE_CONFIRMED` and `ATTRIBUTION_UNRESOLVED` are unreviewed. `EDITORIAL_PARAPHRASE` never renders as a quotation. `WRONG_MISSED` maps to the display key `MISSED`; the raw value remains in `release`. Supplied outcome enums remain unchanged in details and CSV exports.

Original intake records receive a separate `reconciliation` object when served, with action, explanation, canonical links, source references, and explicit no-redirect/retain-original decisions. This does not mutate their imported fields or confer a score. Curated and original arrays are separate; aggregate metrics only consume curated records.

Publication years are attributed, not asserted to be checked original first editions. Approximate navigation intervals are retained in `release.target`; they are not numeric exact deadlines. `full_achievement_documented_by_year` never populates `firstAchievementYear`. Exact drift requires an explicit supplied exact observation; K033's interval cannot enter default aggregates.

The current UI displays all 13 taxonomy entries even when a category is empty. Counts and filters are based on canonical versions, not 88 minus duplicates. Category outcome counts are descriptive, not an accuracy ranking.

## Historical v0.1 curation mechanism

These files remain for compatibility with the original intake pipeline. They are not a way to overwrite immutable v0.2 assessments. For new research, add a versioned evidence release and an entry in `docs/CHANGELOG.md`.

Existing candidates: add `{ "id": "AUD-001", "changes": { ... } }` to `data/curated/overrides.json`. A nested update replaces the entire nested object, so copy that object from `data/generated/predictions.json` before editing. The override schema rejects unknown fields and immutable provenance changes.

New records: add a complete object to `data/curated/predictions.json`. Reuse the structure of a generated record, change its identity and content, and provide actual provenance. Set canonical status and review state only when the corresponding decisions are supported. Keep synthetic development fixtures under `tests/`, outside the import path.

Run `npm run data:import && npm run check && npm run build`. Generated files, all stable pages, downloadable JSON, table filters, group comparisons, and summary statistics rebuild from the curated data without UI edits.
